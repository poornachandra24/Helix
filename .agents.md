# Helix Codebase Agent Guidelines

Welcome, Agent! This document outlines the development standards, code quality guidelines, and pre-push verification checks required for contributing to the Helix codebase.

---

## 1. Quality Control & Pre-Push Hook

To maintain high standards and prevent CI/CD check failures on Pull Requests, **always** run these verification checks locally before pushing code to the remote repository.

### Manual Verification Checklist
Run these commands in order from the repository root:

```bash
# 1. Format Check
cargo fmt --all -- --check

# 2. Clippy Linter Check (Strict - No Warnings allowed)
cargo clippy --all-targets --all-features -- -D warnings

# 3. Unit & Integration Test Suite
cargo test --all-targets --all-features
```

### Git Pre-Push Hook Setup
To automate this verification, you can configure a local Git pre-push hook. Create/edit `.git/hooks/pre-push`:

```bash
#!/usr/bin/env bash
set -e

echo "=== Running pre-push checks ==="

echo "1. Checking formatting..."
cargo fmt --all -- --check

echo "2. Running Clippy linter..."
cargo clippy --all-targets --all-features -- -D warnings

echo "3. Running test suite..."
cargo test --all-targets --all-features

echo "=== All checks passed! Proceeding with push. ==="
```
*Note: Make the hook executable with `chmod +x .git/hooks/pre-push`.*

## 2. Commit Message Standards

Helix follows **Conventional Commits** to automate SemVer releases and changelog compilation via Release Please.

- **Format**: `<type>(<scope>): <description>`
- **Types**:
  - `feat`: A new feature (causes minor version bump, e.g., `v0.2.0` -> `v0.3.0`).
  - `fix`: A bug fix (causes patch version bump, e.g., `v0.2.0` -> `v0.2.1`).
  - `docs`: Documentation changes.
  - `style`: Formatting, missing semi-colons, etc. (no production code change).
  - `refactor`: Refactoring production code without behavior changes.
  - `test`: Adding missing tests or correcting existing tests.
  - `ci` / `build`: CI configuration, cargo dependency updates, build tooling.
  - `chore`: Maintenance tasks.

## 3. Architecture & Style Guide

- **Rust Version**: Built using Rust **2024 Edition**.
- **Raw Mode Operations**: When wrapping output or capturing interactive stdin keys in `src/cli/repl.rs`, **always** print carriage returns (`\r\n`) instead of bare newlines (`\n`) to prevent diagonal layout cascading.
- **RawModeGuard**: Use the RAII `RawModeGuard` struct to ensure raw terminal mode is safely disabled upon function exit or panic.
- **Comfy-Table Wrapping**: When rendering tabular feedback (e.g. agent confirmation cards), query the terminal width dynamically and constrain table column widths rather than hardcoding columns.
- **API Key Redaction**: Never print secrets, HTTP headers (`xi-api-key`, `Authorization`), or Bearer tokens in logs, outputs, or confirmation cards. Always run payloads through the `redact_secrets` utility.
- **Dependency Minimization**: Favor Rust standard library parsing over pulling in heavy external crates (e.g., regex engines for simple string patterns) to keep the compile times fast and binary size small.
